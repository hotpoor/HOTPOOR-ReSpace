根据 2026-09-28 至 2026-09-30 的会话、运行日志与文件核对整理。采用事后汇总形式，不虚构逐分钟的工程记录。私人素材与原始路径不随本日志公开。

## 2026-09-28：从问方法到跑通素材

起点是理解全景视频如何参与三维重建。我们沿 X5 的线索发现 Spirula 与 AWS 开源工具箱，并选择先完成 Spirula 路线。验证机器使用 RTX 3090 24GB 和约 64GB RAM，输入为 X5 原始双鱼眼视频。

先跑前 30 秒，完成 60 张图抽取、全部注册、6,000 步训练和 PLY 导出，证明链路可用。随后按用户要求跑整段 390.88 秒：390 个同步时刻、两个镜头合计 780 张图，最终 706 张注册。

完整 SfM 的首次 `pairs auto` 选择了 303,810 个穷举对。核实进程后停止该任务，复用已有特征，改为 `prefilter` 加时序预筛，候选减少到 22,484 对。记录这一修正是为避免下次盲目接受 auto，不是证明所有视频都该使用同一匹配设置。

训练达到 30,000 步与 200 万高斯，日志记录约 37 分 38 秒；完成评估与 PLY 导出。详细指标见 [实施策略](IMPLEMENTATION_STRATEGY.md)。最终结果仍有明显画质问题，不能写成完成商用交付。

## 2026-09-29：让结果能够被实际检查

本地网页先提供短片与完整版切换、拍摄位置跳转、PLY 下载。根据实际操作反馈增加 WASD、升降、速度控制和原地转头。内置浏览器拒绝 pointer lock，增加按住鼠标拖动转向的兼容方式，随后按用户偏好支持中键。

自动加入完整版菜单的 PowerShell 脚本因中文编码解析失败。训练本身已经完成，但菜单没有更新；检查状态时发现并修复编码，再生成 706 个视点并发布模型清单。这次失败说明“训练完成”和“查看页已接上”必须分别验收，不能提前承诺后台脚本一定成功。

引入官方 SuperSplat Viewer 1.36.0，本地安装、读取同一份 492,600,460 字节的 PLY。确认模型可显示且可转向；没有上传场景到 SuperSplat 平台。暂停默认镜头动画，并对模型和相机一起作 Z-up 到 Y-up 的显示转换。尚未做统一视角、统一参数的定量播放器性能基准。

## 2026-09-30：把路线讲清楚并建立项目

解释过程中明确纠正：“原生支持鱼眼输入”不意味着本次训练不转换投影。保存配置确认 `warp_to_pinhole=true`；完整训练日志确认 661 个输入展开为 3,305 个训练视图。

制作可交互的鱼眼教学演示：真实原图和估计镜头参数，五个轴向透视图，原图边界与像素对应点。演示固定 90° 窗口，区别于训练内部裁边，不称其为训练中间结果的精确复刻。

用户选择项目名 **HOTPOOR-ReSpace** 并明确要求 GitHub 仓库公开。将页面、依赖清单和本地服务器从下载验证目录整理到独立项目，真实图片、视频、相机轨迹和模型仍留本机。

用户随后要求把路线、实施策略和产品判断整理成 SKILL、开发日志与开发传记，并明确 MipMap 的关注点是价格、版别和照片数量限制。于是单独核查官方价格与功能边界，把产品判断与实验结果分别记录。

用户进一步纠正叙述重点：在我们使用 MipMap 的过程中，agent 无法在中间调整和学习；沿 X5 线索发现 Spirula 和 AWS 才是路线发展的实际经过。因此文档以 agent 能检查中间过程、修改、验证并沉淀经验为主线，不将跨产品能力对齐设为项目目标。同步将这条反馈加入实施策略与可复用技能。
