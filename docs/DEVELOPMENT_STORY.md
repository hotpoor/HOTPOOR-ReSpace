# ReSpace 开发传记：既然机器在我手里，路线能否也在我手里

这篇记录依据用户在项目中的选择与实际开发过程整理。引号内是本轮明确表达；其余为对动机和过程的归纳，不冒充逐字访谈。价格事实集中在[核查记录](MIPMAP_PRICING_REVIEW.md)，实验事实集中在[开发日志](DEVELOPMENT_LOG.md)。

## 从一个全景相机的问题开始

ReSpace 的起点不是先决定造一套软件，而是想弄清楚：手里的全景相机，能不能把真实房间变成可以走进去看的三维空间？看到别人的案例以后，问题很快变得具体——它怎样处理鱼眼图，和 MipMap 的路线有什么区别，还有哪些项目真正用过 X5？

解释不足以回答这些问题。于是把自己的 X5 素材拿来，先跑一段，再跑完整视频，要求拿到 PLY，并在网页中实际走动。工作的中心由“某个产品说它能做到什么”转向“这份素材在这台机器上到底能得到什么”。

寻找路线时，X5 是重要线索：沿着全景相机、双鱼眼输入和重建案例继续查找，我们发现了 Spirula 和 AWS 开源三维重建工具箱。随后选择先把 Spirula 跑完整；AWS 路线则只验证了全景转换模块，保留为后续探索方向。

## 为什么对 MipMap 的方案产生保留

用户明确提出的关注点是：“价格”“版本限定”和“照片数量限制”，随后进一步说明：在我们使用 MipMap 的过程中，不能让 agent 在中间有所调整和学习。这是这次实际使用经历中的限制，也是选择另一条路线的重要原因。

我们希望 agent 能读到中间结果和日志，发现问题后调整参数或实现，验证调整是否有效，再把经验写回项目与 SKILL。这里的“学习”指积累可复用的操作经验，不是在线训练 agent 的模型权重。这一诉求来自我们的工作方式，不推断 MipMap 所有产品或接口都没有扩展能力。

真正的不适配来自产品与使用者之间的关系：用户已经准备相机、素材、显卡、电力和等待时间，当本地工作流又受软件档位与任务规模门槛约束时，就会追问自己付费买到的究竟是什么，以及能不能选择更适合自身需求的路线。

官方价格研究让问题落到了可核对的条款上。Desktop 以每任务图片数划分部分档位，Lite 又有独立的年订阅与永久方案；永久授权也不天然等于未来所有大版本免费。与此同时，官网不同页面的永久报价存在差异，Lite 图片上限还没有得到明确结论。这些都应保留在记录中，而不是把所有不确定性整理成一句“它很贵”。

这里的立场是：软件劳动可以收费，稳定性、效率和支持都可能有价值；但对于偏重本地、希望能反复试验和控制流程的人，收费边界应当清楚，价值应能被解释。ReSpace 要尝试的是让这类用户保有另一种选择。

## 让 agent 参与中间过程

Spirula 路线上已经出现了具体的调整机会：完整视频定位时，自动匹配选择了 303,810 个图像对；检查后复用已有特征，改用预筛与时序约束，候选减少到 22,484 对。之后又根据配置和日志修正鱼眼训练的解释，把查看器的中键操作、发布脚本的编码问题逐项处理并记录下来。

这些经验能进入下一次任务：先检查已有产物，避免重复计算；先看实际配置，避免把宣传词当作实现；分别验收训练和网页发布，避免把其中一个成功当成全部完成。ReSpace 要持续保留这种检查、调整、验证和积累的能力，让每次使用都能改善下一次的流程。

## 这条路线没有想象中那么高的新增算力门槛

实验使用已有 RTX 3090，在本地完成了完整视频的定位、训练与导出。训练阶段约 38 分钟，输出 200 万高斯。没有为这次训练额外租云 GPU，也没有按任务购买重建额度。

这正是用户那句“都在用用户本地显卡了”所指向的实际问题：当已有硬件能够完成核心计算，成本叙述就应该区分算力消耗与软件许可，而不是把本地计算想当然地当成必须持续购买的云服务。

但“新增现金支出较低”和“总成本低”仍有距离。硬件不是免费来的，采集与排错花了时间，后续还有清理、补拍、适配和维护。此次结果也没有达到精确建模或高质量商业交付标准。我们得到的是一条可运行、可检查、可以继续改进的路线，而不是已经证明比所有商业产品更省钱。

## 能显示，不代表能好好用

模型导出以后，用户首先遇到的是浏览体验：只靠绕点旋转太慢，于是加入 WASD，再把中键改成原地转头。这里没有引入新的重建算法，却明显改变了检查空间的方式。对使用者而言，“能生成”之后还有“能走进去看清楚”。

随后把同一份 PLY 放进 SuperSplat，本地保留两个播放器入口。这一步刻意把播放器与模型分开：换播放器能够改变交互和显示方式，但画面里的缺损仍需要回到素材、定位和训练处理。

连流程说明也要可验证。曾经把“原生鱼眼支持”说得过于简化，检查配置后补充说明：本次先用鱼眼定位，训练时再展开透视视图。再用真实画面做一个能指向像素的演示，让“重新投影”成为看得见的过程，而不是听上去高深的术语。

## 为什么叫 ReSpace

项目最终选择 **HOTPOOR-ReSpace**。它承接的是把真实空间重新带到浏览器里的目标，也承接了这次开发中逐步明确的偏好：处理可以在本地，数据由用户掌握，结果可以导出，工具可以切换，失败能够解释。

下一阶段的任务不是先宣称替代谁，而是把已经跑通的路线整理可靠：记录每一步、保留证据、减少重复劳动、逐步改善画质，再决定哪些能力值得产品化。

如果未来收费，ReSpace 应把软件能力、维护支持、专业交付和可选云服务的价值讲清楚。不要把用户已有的算力说成平台提供的资源，也不要因为走了本地路线，就抹去开源作者和工程维护者的劳动。

这份传记记录的是一次选择：在现成产品之外，把自己的素材真正跑一遍，并保留继续理解和改进它的能力。
