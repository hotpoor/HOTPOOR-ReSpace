# ReSpace 全景相机路线

以可复核的本地重建结果为目标。接续已有任务时先读日志、清单与进程状态，不从抽帧重新开始。核心阶段为素材检查、抽帧、定位、训练、导出、查看；分别报告完成状态。

本项目沿 X5 线索发现 Spirula 和 AWS 路线。用户重视 agent 能参与中间过程、调整并积累经验；实施时保留可读日志、配置和产物，把经验写回运行手册与技能。

## 调整与经验积累

每阶段先读取证据，再说明问题与修改理由；保存原配置，只重跑受影响阶段，核对修改后的结果。记录输入范围、工具版本、前后参数、耗时、结论和适用条件。接续任务先应用相关经验，不能把一次有效设置当作通用答案。学习指经验持久化与后续复用，不是模型权重在线训练。自动调度尚未实现时，不把人工协调的流程说成已有自动化功能。

## 根据任务读取

- 跑通或修复 Spirula：读 [运行手册](references/runbook.md)。命令以实测版本为例，新版本先查看本机帮助。
- 比较费用、写开发记录：读 [证据与产品判断](references/evidence.md)，并在项目仓库读取 docs 下的最新实施策略、价格核查与日志。
- 本机项目默认可在工作区的 HOTPOOR-ReSpace 目录发现；不要假定其他机器具有相同盘符、WSL、GPU 或数据。

## 关键判断

1. 区分原始双鱼眼、拼接 ERP 全景和普通透视输入。X5 的两个镜头是同步双流，不是把任意视频左右硬切即可。
2. 先小片段证实链路，再运行用户授权的完整范围；参数和资源预算应按素材调整。本次 1 Hz、30,000 步、200 万点是验证配置，不是通用质量标准。
3. SfM 注册率、重投影误差、覆盖、分裂模型与 rig 推断分别检查。高注册率不等于正确几何。
4. 检查实际训练配置和展开后的视图数。原生鱼眼定位与训练转透视可以同时存在；不得仅凭产品宣传解释实现。
5. 训练结束、最终文件可读、查看器加载、视觉质量验收是不同结论。后台发布必须检查错误日志与 HTTP 结果。
6. 同模型播放器对比先保持 PLY 不变；压缩、降采样、LOD 后另作标识。模型和相机一起转换坐标，保留原文件。
7. 私人照片、模型、视点、日志与生成场景页保持本地；公开仓库只提交代码、去私密数据的说明与允许发布的资产。

## 解释与交付

讲解投影时用实际图像与标定参数，说明透视视图的方向、有效区和像素映射。没有复用训练内部裁边与插值实现的演示，明确标为教学近似；不要用生成式图像伪装真实重建步骤。

交付应包含可用查看入口、操作方式、数据覆盖、实际耗时、可见缺损、产物位置与下一步。成本说明分开计入本地硬件、电力、人时、软件服务和可选云费用。不能把“不买云算力”写成“没有成本”，或把不同素材的运行时间当成性能胜负。
